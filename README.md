# رزرو آنلاین دیت با Flask

این نسخه با کمترین تغییر نسبت به ساختار قبلی، باگ‌های اصلی، ناسازگاری فرم‌ها و چند مشکل امنیتی را اصلاح می‌کند.

## اجرای محلی

```bash
python -m venv .venv
.venv\Scripts\activate  # ویندوز
pip install -r requirements.txt
```

برای ورود به پنل مدیریت، قبل از اجرای برنامه مقدار `ADMIN_PASSWORD` را تنظیم کنید.

ویندوز PowerShell:

```powershell
$env:ADMIN_PASSWORD="یک-رمز-قوی-اینجا"
python app.py
```

سپس:

- سایت: `http://127.0.0.1:5000/`
- پنل: `http://127.0.0.1:5000/admin`
- Health check: `http://127.0.0.1:5000/health`

## استقرار روی Render

1. محتوای این پوشه را در ریشه GitHub repository قرار دهید.
2. در Render گزینه **New → Blueprint** را بزنید و repository را انتخاب کنید.
3. مقدار `ADMIN_PASSWORD` را در Environment وارد کنید.
4. `SECRET_KEY` توسط Render تولید می‌شود.
5. پس از Deploy، سایت در `/` و پنل در `/admin` قرار دارد.

## نکات مهم

- تاریخ‌های صفحه انتخاب تاریخ دیگر هاردکد نیستند و به‌صورت خودکار از امروز و برای ۱۴ روز آینده ساخته می‌شوند.
- نام فیلدهای latitude/longitude در فرم و Flask یکسان شده است.
- routeهای قدیمی `book` و `location` نگه داشته شده‌اند تا لینک‌ها/بوکمارک‌های قبلی BuildError ندهند و روند اصلی سایت تغییر نکند.
- رمز ادمین دیگر مقدار پیش‌فرض `1234` ندارد.
- `SECRET_KEY` دیگر مقدار ثابت و قابل حدس ندارد.
- کوکی session با HttpOnly و SameSite تنظیم شده و روی Render به‌صورت Secure فعال است.
- تاریخ، ساعت و مختصات سمت سرور نیز اعتبارسنجی می‌شوند و فقط به اعتبار JavaScript مرورگر تکیه نمی‌شود.
- لوکیشن انتخاب‌شده در پنل مدیریت نیز قابل مشاهده است.
- شماره تماس پیش‌فرض از `DEFAULT_PHONE` قابل تنظیم است.

### SQLite روی Render

SQLite در محیط‌های بدون دیسک پایدار ممکن است با restart/redeploy اطلاعاتش را از دست بدهد. برای اطلاعات مهم و دائمی، PostgreSQL یا یک دیسک پایدار لازم است. این نسخه عمداً دیتابیس را به PostgreSQL منتقل نمی‌کند تا ساختار و روند فعلی پروژه تغییر اساسی نکند.
